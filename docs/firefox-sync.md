# Firefox Sync

Sync is shared with tennessine through dubna: its C++ adapters (`dubna/src/chrome/browser/firefox_sync/`) connect Chromium's password, bookmark, history and autofill stores to `dubna/rust/oganesson_sync`. Desktop's side, the tabs adapter, the synced-tab views and the account on the profile, implements dubna's `firefox_sync_platform.h` in `src/chrome/browser/firefox_sync/platform/`. The Rust library uses pinned Mozilla application-services crates for account and Sync protocols. It loads beside the browser as `liboganesson_sync.so`, using the browser's NSS, or on Windows as `oganesson_sync.dll`, with its own NSS ([Windows](windows.md)).

The retained implementation uses OAuth with PKCE, encrypts saved account secrets through Chromium's OS cryptography service, and routes HTTP through the profile's network context. Signing out discards pending results. The client must honor server backoff and preserve local edits made during a sync.

Supported implementation scope: passwords, bookmarks, history, open tabs, addresses, and payment methods. Bookmark keywords and separators stay in the Sync store (places) only: the browser never sees them, and Sync keeps them in place for Firefox. Containers are parked ([goals](../goals.md#parked)), so nothing syncs them. While Settings → Privacy → "Don't save browsing history" (`history.saving_disabled`) is on, history doesn't sync: its switch is off and greyed out, and a sync under way when it is turned on applies no history.

Other devices' open tabs show where Chromium shows synced tabs: History → Tabs from other devices (linked from the Sync settings), the app menu's History → Recent tabs, and the `chrome.sessions` API. `src/chrome/browser/firefox_sync/platform/remote_tabs.cc` turns them into Chromium's synced sessions, one window per device, and `oganesson/core/firefox-sync-remote-tabs.patch` lets the `SessionSyncService` return them while Chromium's own tab sync is off. Tab search doesn't list other devices' tabs.

Tabs go between devices as in Firefox, through Mozilla accounts' device commands rather than the sync server. "Send to device ▸" in the page, link and tab context menus lists the account's other devices that take tabs, Firefox ones included, and "All devices" (`src/chrome/browser/firefox_sync/platform/send_to_device_menu.cc`, wired in by `oganesson/ui/send-to-device.patch`). A tab another device sends opens in the background, with a system notification that switches to it. A request from Firefox to close tabs here closes every open tab at a URL it names: Firefox names tabs only by URL. In History → Tabs from other devices, each tab of a device that takes such requests has a close button (`oganesson/ui/close-synced-tab.patch`); the tab stays hidden until that device's next sync. Both directions wait for a sync, every 30 minutes or after a local change, until dubna polls more often (zakius/dubna#3).

The account shows like a Google one would: `desktop_platform.cc` gives the browser profile the Mozilla account's name and picture (Chromium's GAIA name and picture fields), so the avatar button, the profile menu and the Sync settings card show them. `oganesson/ui/firefox-sync-avatar.patch` keeps them across restarts and shows "Sync paused" on the avatar button while the account must sign in again.

`python3 tools/check_firefox_sync.py` exercises the built library against the local fake server. `./oganesson.py test firefox_sync` exercises the browser path. These checks must pass on the extracted build. They are not evidence of a real Mozilla-account test.

Before using this build with personal data, verify sign-in and two-way additions, edits, deletions, restart, and sign-out with a dedicated Mozilla test account and Firefox/Fenix. The original source documented no completed real-account verification and used an example application's OAuth client ID. Review that client identity before distribution. Use a fresh browser profile for validation.
